# Guided Operations Visual Decision Log

## Reference fidelity without demonstration data

The supplied reference PNG is used for hierarchy, spacing, light/navy/gold balance, action depth, angled shell cues, and scenic composition. Its employee portrait, names, incident rows, notifications, service details, checklist, activity, quote, clock, and version are not product requirements and are not copied into production fallbacks. Automated screenshots use fictional authorized API fixtures only.

## Scenic placement and transfer size

- The correctional-perimeter/watchtower scene is Home-only. Working officer routes and administrator routes retain neutral headers so editors, forms, and tables keep their working space.
- The raised mountain landscape is a decorative shell image below the navigation. It fades into solid navy before reaching labels and has no text layered into its detailed terrain.
- The higher-fidelity WebP replacements are larger than the original generic SVGs, but the selected Home hero plus sidebar transfer is 63,604 bytes. The sidebar alone is 6,350 bytes. Responsive media-qualified preloads avoid downloading every hero crop.
- Reduced-data, failed-image, forced-colors, and print conditions preserve navigation, labels, actions, and light/navy fallback surfaces.

## Brand, fixtures, identity, and session context

- Retain the project-owned code-native shield. No facility crest or real insignia is introduced.
- Keep the four action fixtures code-native and inline. They use one SVG/stroke/material contract and add no external license or layout-shift dependency.
- Use authorized display-name initials as the profile fallback. No portrait source, biometric image store, upload, or revocation system is implied.
- Shift remains visible in the Home hero because it scopes date/shift work such as Count Sheet. The profile menu repeats it only as subordinate session context, not as an equal page heading.

## Operational truthfulness

- `Online` and `Offline` come from the browser connectivity signal. They do not claim API, database, AI, or synchronization health.
- No “last synced” time is shown because the shell has no trustworthy cross-feature synchronization timestamp.
- No notification badge, daily checklist, activity feed, Help panel, detailed service health, or Daily Paperwork shortcut is added until its data contract, authorization, destination, loading, empty, and error semantics exist.
- Home calls approved forms `Quick Forms`; it does not claim usage ranking.
- Unknown, empty, error, physical-only, and retry states remain explicit. No sample operational values become production fallbacks.

## Density and interaction

- Officer Home uses the strongest feature depth and a bounded content width. Document Studio, Count Sheet, Paperwork Center, and other working routes remain wider and flatter.
- Administrator pages use the same semantic tokens with denser spacing and table layouts rather than a separate visual language.
- Hover travel is limited to pointer-capable, no-motion-preference environments. Keyboard focus, active compression, disabled treatment, and forced-colors boundaries do not depend on shadows alone.
- Official paperwork print rules remain isolated from screen decoration and are verified separately from screen visual baselines.
